# Three.js 3D 行政区地图 · 实现要点与参数经验值

> 面向需要进行二次开发的场景：说明渲染管线各环节的取值依据与推荐参数。
> 参考实现：`assets/app_template.js`（约 960 行，可直接当骨架用）。

## 1. 技术选型

| 决策 | 选择 | 原因 |
|---|---|---|
| 渲染库 | three.js r147 UMD + examples/js 版 OrbitControls | r148 起移除了 `examples/js`（非 module 版），r147 是最后能"双击 HTML 直接跑"的版本 |
| 模块方式 | 经典 `<script>` 标签 | ES module + import 在 `file://` 下被 CORS 拦截；交付物必须能双击打开 |
| 交付形态 | 单个自包含 HTML | 全部内联（含 three.min.js 约 600KB），离线可用 |
| 行政区边界 | 阿里云 DataV GeoAtlas `https://geo.datav.aliyun.com/areas_v3/bound/{adcode}.json`（+`_full` 取下级行政区） | 免费、无需 key、带 centroid |
| 简化算法 | Douglas-Peucker，省界 eps≈0.012°，下级 eps≈0.008°，碎块面积阈值 0.0009°² | 省界 791 点 → 375 点，肉眼无损 |

## 2. 坐标系与比例尺

```
x = (lng - centerLng) * cos(midLat) * S     // 经度方向按中纬度余弦压缩
z = -(lat - centerLat) * S                  // 屏幕上北为 -z
S(每纬度世界单位) ≈ 900 / 纬度跨度          // 让地图高度落在 55~60 单位，与 fov45 的默认相机匹配
```
- **不要**用真实高程比例（山高/省宽 ≈ 0.004，根本看不见）。用夸张系数 `vert`：平原区 1.5~2，山地区 2~3。
- 网格分辨率 `SEGX=280, SEGZ=420`（约 11.8 万顶点 / 23 万三角形）。再高在软渲染下会掉帧，再低山体会糊。

## 3. 地形高度函数（视觉决定成败的部分）

```
h = base(0.34) + Σ 各山脉 max(高斯脊) - Σ 各盆地(高斯) + 多频噪声
```
- **山脉用"取 max"而不是累加**：一条山脉由 4~6 个中心点组成，累加会炸出雪堆状尖峰；对每条山脉取中心点高斯的最大值，得到平顺的山脊。
- **山脊半径 r 的经验值：0.15°~0.19°（约 15~20km 半宽）**。
  取值说明：r 过小（<0.14°）时，一个山头在网格上只覆盖少数格子，会呈现锥形尖峰；取 0.15~0.19 且中心点间距拉开到 ≈r，才会形成连绵脊线。
- 盆地（太原/临汾/运城这种）单独下凹 -0.5~-0.65，让城市所在的河谷低下去，山与谷的对比才成立。
- 噪声用 6 个不同频率的正弦叠加（波长 0.27°→2.5°），给山体增加岩石质感；频率别超过网格可分辨上限。

## 4. 省界裁切 + 地市色块（一图两用的关键技巧）

**用一个 canvas 同时做"色块贴图"和"alpha 遮罩"：**
1. 1100×1450 的 canvas，把省界多边形填白（RGB=白，A=255），省界外留透明（A=0）；
2. `clip()` 到省界后，给每个下级行政区填 `rgba(cityColor, 0.30)`，再画彩色界线；
3. 作为 `map` 给 `MeshStandardMaterial`，并设 **`alphaTest: 0.5`（不要设 transparent）**——这样地形走不透明渲染队列、正确写深度，边界干净无排序问题。

再补两件套让它像一块"剖开的沙盘"：
- **侧壁（skirt）**：沿省界每点生成上下两个顶点（上=地形高，下=BOTTOM），连成三角带。**必须用 `MeshBasicMaterial` + 顶点色渐变**，不能用受光材质——背光面会变成死黑一片。
- **底板**：ShapeGeometry 放在 BOTTOM 处，防止从下方看穿；再叠一层放大 1.8%、半透明的金色 halo 做"悬浮感"。

## 5. 光照（最容易过曝的地方）

实测调出的稳定值（配合 `ACESFilmicToneMapping`, exposure 1.0）：
```
HemisphereLight(0xbcd4ff, 0x2a2218, 0.36)
DirectionalLight(0xffe2b8, 0.72)   位置 (MAP_W*1.25, 42, -MAP_H*0.15)  // 太阳放低才出立体感
DirectionalLight(0x6ea8ff, 0.18)   反向补光
AmbientLight(0xffffff, 0.13)
```
- 说明：最初 sun=1.15 + hemi=0.62 + amb=0.26，山体全部泛白成蜡状。**总辐照度超过 ~1.3 就会过曝**。
- 地形高程配色用 8 档渐变（深绿→橄榄→黄土→岩灰），**最高档不要给纯白**（会像雪原）。
- 地形材质开 `flatShading: true`：低多边形面片感比平滑着色更像"3D 沙盘"，还能掩盖高斯函数的平滑感。

## 6. 标签（sprite）的屏幕恒定尺寸

```
SpriteMaterial({ sizeAttenuation: false, depthTest: false })
scale = 0.030~0.032          // 换算：屏幕像素 ≈ scale × 1147（在 950px 高的视口下）
```
- `sizeAttenuation:false` 让标签在任何缩放级别都是同样大的字（世界单位缩放在远景会小到 7px 无法阅读）。
- **必须按距离分级显示**，否则 74 个标签糊成一团：star3 在 `<135` 单位内显示，star2 `<56`，star1 `<36`，悬停/选中/在当前线路上时强制显示。
- opacity 做缓动淡入淡出，`label.visible = opacity > 0.02` 省渲染。

## 7. 景点标注的密集避让

- 220 轮力导向松弛：间距 < 1.62 世界单位（约 18km）的标注互相推开，**单点位移上限 0.92 单位（约 10km）**——超出会让人产生方位误解。
- 位移超过 0.03 时画一条淡色引导线连回真实坐标。
- 图标抬升：光柱 1.55 + 模型悬浮，模型 9 种类型全部程序化生成（共享几何体缓存 + 共享材质缓存，868 mesh / 31 万三角形在真 GPU 上毫无压力）。

## 8. 河流飘带

- `CatmullRomCurve3` 平滑折线 → 沿法线展开成三角带，宽度中段略窄（`0.55+0.45*sin(t*PI)`）做出自然收束。
- y = `H(lng,lat) + 0.08~0.10`，贴着地形走。
- **界外钳制**：黄河沿省界走，坐标稍偏就落到界外悬浮。写一个 `ensureInside()`：不在界内就沿"该点→区域中心"二分搜索，拉回界内 0.014°。所有河流点都必须过这一步。
- 配色写实：黄河用浑金色 `0xd9a441`，其他水系用蓝 `0x4fb8e8`。

## 9. 推荐线路飘带

- **不能用 AdditiveBlending**：亮色地形上叠加后白化，几乎不可见（实测）。
- 正确做法：同一条几何体克隆两份——宽的暗色描边带（0.34，`0x05222c`，op .55）+ 窄的亮色主线（0.16，`0x5fd3f3`，op .95），普通混合，任何背景都清晰。
- y = `H + 1.05` 抬高避开山体遮挡。

## 10. 相机与交互

- 默认机位：`pos = (MAP_W*0.66, 52, MAP_H*0.64)`，`target = (≈0, 1.2, 0)`。fov45 下正好把 55~60 单位高的地图装进画面。
- 点选景点飞行：保持当前方位角 az，仰角固定 0.74rad、距离 21 单位，950ms 三次缓动。
- 键盘漫游：WASD 沿视线水平分量移动，QE 升降，速度 26 单位/秒。
- 点击判定：pointerdown 记录坐标，pointerup 位移 > 5px 视为拖拽不触发选择（否则旋转地图会误开卡片）。
- 遮罩点击区域用 `SphereGeometry(1.05)` + `material.visible=false`，只参与 raycast。

## 11. 无头验证（Playwright）

```bash
NODE_PATH=<node workspace>/node_modules node smoke_test.js <html> <outdir>
```
- **必须显式指定 `executablePath`**：playwright-core 的版本号通常 > 本机已装浏览器版本，不指定会要求下载 1243 而本机只有 1228。
- 启动参数必须带 `--use-gl=angle --use-angle=swiftshader --enable-unsafe-swiftshader`，否则 WebGL 直接黑屏。
- **软渲染只有 ~3 FPS**：相机飞行动画 19 帧需要 6~12 秒才走完。测试里截图前等 10s+，否则会把"动画没播完"误判成 bug。
- 判定标准：0 个 console/page 错误、`#list .item` 数量 == 景点数、三张截图肉眼检查（全景/详情卡/夜景+线路）。

## 13. 已知边界情况

- 同城密集区（如平遥古城/双林寺/镇国寺相距 6~12km）标签仍可能重叠，属于可接受范围；避免给同一县城塞 5 个以上景点。
- 相机飞到紧贴省界的景点时，侧壁会进入画面近景。侧壁已做无光照处理不至于刺眼，但尽量让默认方位角从区域内部方向看。
- 山脉/盆地/河流数据是手工整理的示意走向，用于视觉表达；若需要精确高程应改用真实 DEM（另行实现）。
