# 内容调研与写作规范（景点知识库怎么做）

> 3D 只是外壳，**内容质量决定这份地图有没有用**。74 条"看点 + Tips"比任何渲染特效都值钱。

## 1. 调研流程

### 第一步：确定骨架（15 分钟）
1. 明确区域和下级行政区（省→地市，或市→区县），拿到 adcode。
2. 用 WebSearch 确认该区域"当前最值得关注"的清单：
   - 查询 A：`<区域> 5A 4A 景区 名单`、`<区域> 必去景点`
   - 查询 B：`<区域> 世界遗产 / 全国重点文物保护单位`（古建大省必备）
   - 查询 C：当年的政策热点（免票活动、新开景区、影视/游戏带火的取景地）——这类信息时效性强，**必须搜，不能靠记忆**
3. 目标数量：省级 60~80 条，市级 30~50 条。少于 40 会显得单薄，多于 100 会稀释质量。

### 第二步：逐条填内容（主体工作量）
每条 spot 需要的核心信息，按这个优先级核实：

| 字段 | 来源要求 | 无法核实时 |
|---|---|---|
| 坐标 lng/lat | 地图服务 / 百科 infobox | 偏差 <3km 可接受（省域尺度上肉眼不可辨） |
| 门票 | 当年官方公告或近期新闻 | 写 `'低价／以现场为准'`，**不要猜** |
| 看点 see | 综合百科 + 游记，写**具体名称/编号/数据** | 宁可短也不要编 |
| tips | 游记里的实操经验（预约、限流、爬山强度、错峰） | 通用建议（带外套/穿运动鞋）兜底 |

### 第三步：反向审计（交付前必做）
- 每条 `see` 里至少有一个**可验证的具体细节**（窟号、年份、尺寸、人物名），全文没有一个的说明没做功课。
- 数字类事实（高度/年份/数量）逐条回查；不确定的删掉数字只留定性描述。
- 官方名单类标签（如"黑神话取景地""世界遗产"）**必须核对官方来源**，宁缺勿滥。
- 票价一律标注"参考价"，UI 已内置免责声明，不要写成确定值。

## 2. 写作口径

### see（看什么）—— 1~3 句，回答"它凭什么值得来"
- **好例子**："北魏皇家石窟，现存主要洞窟45个、造像5.9万余尊。第5窟17米高的坐佛与第20窟著名的露天大佛、第6窟'石刻连环画'佛传故事最不能错过。"
- **坏例子**："云冈石窟历史悠久，气势恢宏，是中华文化的瑰宝，非常值得一去。"（全是形容词，零信息量）
- 小众点的写法：一句话说清独特价值 + 一句"怎么进/怎么去"的关键提示。

### tips —— 3~5 条，全是"去过才会知道"的事
按价值排序，优先覆盖：
1. 路线/顺序建议（按什么顺序走、体力怎么分配）
2. 预约/限流/开放时间（最容易白跑一趟的点）
3. 摄影/观看的最佳时机与机位
4. 交通串联（和谁同一天、相距多远）
5. 反直觉的坑（禁闪光、登临另收费、恐高慎选、冬季封山）

### star（推荐等级）—— 编辑判断，无事实风险
- **3 必打卡**：出了省也值得专程去（世界遗产、顶级古建、头部自然景观）
- **2 强烈推荐**：到了这个市应该安排
- **1 小众宝藏**：顺路 / 同好向（小众国保、地方性景点）

### tag —— 用于筛选与徽章
常用值：`世界遗产` `世界文化景观遗产` `国家5A` `国保` `免费` `夜游` `红色` `寻根` `演艺`
以及区域特色主题（如山西的 `黑神话取景地`，需在 region.js 的 extraFilters 里注册对应筛选器）。

## 3. 分类（cat）与图标（icon）的对应

| cat 常见取值 | icon |
|---|---|
| 古建 / 佛教 | temple |
| 古镇 / 古城 | town |
| 晋商 / 民居 / 庄园 | courtyard |
| 山水 / 山岳 | mount |
| 石窟 | cave |
| 红色 | museum（纪念馆）/ mount（战斗遗址峡谷） |
| 博物馆 | museum |
| 水文 / 湖泊 | water |
| 瀑布 | fall |
| 长城 / 关隘 | gate |

cat 值会自动生成筛选 chip，**每个分类下至少要有 2 条**，否则筛选后显得空。

## 4. 线路（region.js 的 ROUTES）设计原则

- 4~6 条，每条 8~14 个点，按**地理顺路**排序（程序会沿点连成飘带，乱序会出现交叉折返）。
- 命名带天数：`晋北古建朝圣 4日`，让用户一眼知道投入。
- 每条线路覆盖 2~3 个 star3 做锚点，中间用小众点填充（这正是这类地图的价值：把顺路的小众点带出来）。
- ids 必须与 spots 的 id 完全一致，写完用脚本核对一遍（漏一个 id 该点就不会上线路）。

## 5. 效率清单（照做即可，别跳步）

1. `fetch_admin_geo.py <adcode>` 拿边界 → 确认城市名与坐标
2. 定 bbox / center / scale / vert 四个参数（见 recipes 第 2 节）
3. WebSearch 定骨架清单 → 写 spots.js（先写 star3，再补 star2/star1）
4. 手工整理山脉/盆地/水系（每个山脉 3~6 个中心点，参考 recipes 第 3 节的半径经验值）
5. 设计 ROUTES 并核对 id
6. `build_standalone.py` 打包 → `smoke_test.js` 冒烟 → 三张截图肉眼检查
7. 反向审计内容（第 1 节第三步）→ 交付
